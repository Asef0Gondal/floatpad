# FloatPad Engineering Notes

Persistent memory of the Electron → Tauri/Rust rewrite: root causes found, fixes
applied, and rules that keep them fixed. Read this before touching the shell.

## Verification workflow (use this, don't guess)

1. **Hidden self-test**: `FP_SELFTEST=1 RUST_LOG=info ./target/{debug,release}/floatpad`
   (vite must be running for dev builds). Shows no window, exercises opacity,
   detach + escape, mini, resize, screenshot overlay, panels, embedded-webview
   create → eval round-trip → destroy, screen capture, and the ad-block
   allowlist + WKContentRuleList compile. Logs `SELFTEST PASS/FAIL` per check.
2. **Unit tests**: `npm test` (vitest, incl. the IPC contract test) and
   `npm run test:rust` (cargo test --lib).
3. **Crash reports**: `~/Library/Logs/DiagnosticReports/floatpad-*.ips` — parse
   the triggered thread's frames; they pinpoint the exact offending call.
4. **JS errors** relay to the terminal via the `log_js` command (index.jsx
   installs window.onerror / unhandledrejection handlers).
5. Self-test waits use **polling, not fixed sleeps** — window registration is
   async and fixed sleeps produced a release-only flake.

## Root causes & rules (each one cost real debugging time)

### macOS AppKit must run on the main thread
Async Tauri commands execute on worker threads. Raw `objc2` calls
(`setCollectionBehavior`, `setAlphaValue`, `setLevel`) off-main trigger
**SIGTRAP** in macOS Sequoia's window management (`NSWMWindowCoordinator`).
**Rule:** every raw AppKit call goes through `run_on_main_thread`; send object
pointers across threads as `usize`, deref only inside the main-thread closure
(`Retained<T>` is `!Send`). See `platform.rs`, `adblock.rs`.

### Tauri default permissions are narrower than they look
`core:window:default` does **not** include `allow-start-dragging` — drag regions
(`data-tauri-drag-region`) were silently denied. WKWebView also ignores
Electron's `-webkit-app-region: drag` CSS entirely.
**Rule:** check `permissions/<plugin>/autogenerated/reference.md` in the tauri
crate source for what a default set actually contains; add explicit permissions
for anything interactive. App-command permissions (`allow-<cmd>`) only exist if
the command is declared in `build.rs` via `AppManifest::commands(&[...])`.

### WKContentRuleList (network-level ad blocking)
- WebKit's `url-filter` regex engine is a restricted subset: anchored patterns
  like `^https?://([^/]*\.)?host([/:?#]|$)` fail with **WKErrorDomain error 6**.
  Plain substring filters (`doubleclick\.net`) compile and match v1's loose
  `host.includes(rule)` semantics.
- Resource type is `style-sheet`, not `stylesheet`.
- `load-type: ["third-party"]` covers ad traffic without touching main-frame
  navigation (v1 skipped mainFrame).
- Allowlist = `unless-domain: ["*host"]` in every trigger; recompile + push into
  live webviews via `userContentController.removeAllContentRuleLists()` +
  `addContentRuleList()` on toggle.
- Compile is async with a completion block; store the result in the block
  (never block the main thread waiting for it).
- Keep `AD_HOSTS` in `adblock.rs` in sync with `page.js` (element-level hiding
  remains as defense-in-depth and as the non-macOS fallback).

### API shape gotchas (tauri 2.12 / objc2 0.6 / plugins)
- Async commands taking `State<'_>` must return `Result` — or be sync commands.
- `global-shortcut` 2.4: `with_shortcut(s)` returns `Result<Self>` and takes no
  handler; use one `with_handler` and match `shortcut.id()`.
- `WebviewWindow` is neither `Deref<Target=Window>` nor `AsRef<Window>`;
  use `win.as_ref().window()` (`AsRef<Webview>` → `Webview::window()`).
- `hwnd()` returns the `windows` crate's newtype `HWND`; unwrap `.0` for
  `windows-sys` functions.
- `Retained::from_raw` returns `Option<Retained<T>>` (objc2 0.6).
- `concat!()` inside `log::info!` breaks implicit format-arg capture; use
  `format!()` as an explicit argument.
- Multi-webview attach is `window.add_child(WebviewBuilder, pos, size)`
  (feature `unstable`); `initialization_script` is main-frame-only by default.
- xcap on Linux needs `libpipewire-0.3-dev` + `libspa-0.2-dev` (CI apt line).

### UX traps
- A fullscreen transparent always-on-top overlay (screenshot capture) sits
  above everything and eats all clicks. **⌘⇧Space is a panic key**: it must
  dismiss the overlay and clear click-through before toggling visibility.
- Click-through (`set_ignore_cursor_events`) has no hover forwarding in Tauri;
  the toggle button itself becomes unclickable. Tray → Show and the panic key
  always restore control and emit `detach-cleared` so the UI stays honest.
- Multiple app instances fight over global shortcuts and stack identical
  windows — the single-instance plugin is mandatory, not optional.

### Data integrity
- `prefs.json` is read-modify-written by move/resize events, panels and adblock
  toggles concurrently: guard with a mutex and write atomically (tmp + rename),
  otherwise updates are lost or the file is torn.

### Flex toolbars overflow silently — reserve a grip, fold don't clip
A `flex-shrink: 0` control group plus a `min-width: 0` spacer means narrow
windows push controls off the edge (invisible, unreachable) and consume the
only drag area. Pattern that works: guaranteed min-width grip strip with
`data-tauri-drag-region`, progressive compression via viewport media queries
(the webview viewport IS the window), and an overflow menu for secondary
controls so nothing is ever hidden. Mini/collapsed modes should be mostly
grip strip. See the titlebar in App.jsx / App.css.

### Never derive app URLs from a live webview's url()
`main.url()` before the first navigation commits is `about:blank` → opaque
origin → `origin().ascii_serialization()` = `"null"` → panel URLs became
`null/index.html?panel=x` (release-only race). Use
`WebviewUrl::App("index.html?panel=x".into())` — Tauri resolves it against the
configured base (devUrl / tauri://localhost) deterministically, and `Url::join`
preserves the query string.

## v2.1.2 full-audit fixes (16 findings)

Rules learned from the A-to-Z audit:
- **WKWebView suppresses `alert`/`confirm`/`prompt`.** wry's UI delegate has no
  text/alert panels, so `confirm()` returns false and `prompt()` returns null —
  features built on them silently die. Use the dialog plugin (`ask`/`message`)
  and inline React inputs. A regression test greps the UI for raw dialogs.
- **Global-hotkey registration can fail at startup** (another app owns the key).
  Register in `setup` with log-and-continue, never `?`/`expect` — a conflict
  must disable one hotkey, not crash the whole app.
- **Autosave user work.** Board and Write pad persist on a debounce + on
  `beforeunload`; a reference app that loses content on quit loses trust.
- **Potato/opacity state:** stash the pre-dim value in a ref; an effect keyed
  only on the toggle reads the already-dimmed value otherwise (stuck at 70%).
- **Eyedropper must replicate the on-screen transform** (flip/rotation) before
  sampling, or it picks the wrong pixel on transformed images.
- **Clean up handoff payloads on window `Destroyed`**, not only on fetch, or
  fast-closed windows leak whole images into the map.
- **Debounce prefs writes** on move/resize (generation-counter delayed task);
  don't read+write+rename the file on every drag pixel.
- **Scope file/asset access** to user-data roots ($HOME, /Volumes, temp,
  app-data) rather than `**`; keeps media working, blocks system files.
- Rules of Hooks: a conditional `return` before hooks is a latent crash — split
  into a wrapper component (App → AppMain / ShotView).

## v2.1.4 — grab handle, borderless view, second-audit fixes

- **Grab handle + borderless** replicate the old Electron focus-mode design:
  left-edge handle uses `data-tauri-drag-region="deep"` (bare attribute only
  drags on the element itself, not its texture child); borderless titlebar is
  `position:absolute` so content fills the window, revealed by a top hotspot.
- **TDZ crashes caught by the JS error relay:** a `useEffect` placed before the
  `useCallback` it references throws "Cannot access X before initialization"
  (deps array evaluates during render). Order effects after their callbacks.
  Same bug class hit `gifSelId` referencing `singleSelectedImage` declared later.
- **Board autosave is file-based** (Rust `autosave_board`/`load_autosave_board`,
  app-data dir, atomic write, off UI thread) — no localStorage 5 MB ceiling;
  flushed on blur/visibilitychange because `beforeunload` is unreliable in Tauri.
- **Task toggle skips fenced code blocks** so preview checkboxes stay aligned
  with source (marked renders no checkbox inside code fences).

## v2.1.5 — lean pass (applied the sound audit findings, rejected the forced ones)

Applied: dead icons/commands removed; theme tokens → CSS `:root` vars (fixed an
invalid light hex `#AEAB A4`); Write counts derived in render; vitest config
merged; `img.decode()`; `tauri::Url`; `tauri-plugin-opener` (covers BOTH
`open_url` and `reveal_item_in_dir`); overlays → native `<dialog>`.

Rejected (would break features/security or re-open fixed bugs): removing
DOMPurify (pasted-markdown XSS), network adblock, `ctx.filter` grayscale
(absent in WKWebView), the selftest, the bounds debounce, regression tests.

**Why Popover API (#15) was skipped:** `popover` elements render in the top
layer, whose containing block is the viewport — so the menus'
`position:absolute` relative to their `tb-menu-wrap` trigger would misposition.
Correct anchoring needs CSS anchor positioning (Safari 26+) or manual JS, which
negates the simplification. The existing ~5-line outside-click dismiss is already
lean and correct. Lesson: a `native:` suggestion isn't a win if the native API's
layout model fights the current design.

**`<dialog>` gotcha:** an inline `onClose` prop changes identity every render;
a `useEffect([onClose])` calling `showModal()` would re-run and throw on an
already-open dialog. Use a mount-only effect + a ref to the latest onClose.

## v2.2.0 — Loop 1: Board undo/redo + hardening

**Changed:** Cmd+Z / Cmd+Shift+Z (and Cmd+Y) undo/redo on the Board, plus ↶ ↷
toolbar buttons. Built as a pure `boardHistory.js` module (create/push/undo/redo,
100-deep cap, redo-tail truncation) with 6 unit tests, then wired into ImageBoard.

**Learned:**
- Snapshot history must be DEBOUNCED (~250ms): the per-image opacity slider fires
  setImages on every tick, which would flood the stack with micro-steps. Discrete
  actions (drag/resize/pen) already commit on mouseup, so they record cleanly.
- A `restoring` ref flag prevents undo/redo restores from being recorded as new
  edits; a `boardReady` gate makes the restored board index 0 (so undo can't walk
  back past the loaded state into an empty board).
- Alias imported predicates (`canUndo as histCanUndo`) to avoid clashing with the
  React state of the same name.
- Fixed a real leak: `shot_open` inserted the image payload BEFORE building the
  window; a build failure left it in the map forever. Now removed on failure.

## v2.3.0 — Loop 2: persistent Shot Library

**Changed:** floated images now persist to `<app-data>/shots/` (image + 160px
thumbnail + index.json with name/tags/created). New Rust store (shots.rs):
shot_save / shots_list / shot_load / shot_delete / shot_update. A `<dialog>`
library UI (grid + search + tag edit + reopen + delete) opened via ⧉ Shots.
Floating auto-saves; reopening from the library passes persist=false.

**Learned:**
- Auto-save-on-float + reopen-from-library would create DUPLICATES unless the
  reopen path opts out → added a `persist` flag to shot_open.
- The self-test shot round-trip must DELETE its test shot (and shot_open uses
  persist=false) so it never pollutes the user's real library.
- Thumbnails generated once at save (image crate `thumbnail`) keep the library
  grid fast; SVG/unsupported formats fall back to copying the original.
- Verified end-to-end in the hidden self-test: save→list→load→update→delete.

## v2.4.0 — Loop 3: Settings, crop, accessibility

**Changed:** a consolidated Settings `<dialog>` (theme / potato / borderless +
clear-board-autosave / clear-shot-library with confirm + version/about). An
undoable crop tool (`✂`): a `<dialog>` with a draggable/resizable crop box over
the image; Apply crops via canvas and replaces the source (recorded by undo).
Accessibility: global `:focus-visible` ring; dialogs use native `<dialog>`
(implicit role/aria-modal/focus-trap). New Rust commands board_autosave_clear /
shots_clear.

**Learned:**
- Crop operates on the untransformed source, so applying it resets flip/rotation
  to match what the crop preview showed (grayscale/opacity are render flags, kept).
- Settings reads the version from package.json via a Vite JSON import — no
  hard-coded version string to go stale.
- Clear-data actions confirm via the dialog plugin (WKWebView has no native
  confirm) and run off-thread in Rust.

## v2.5.0 — Loop 4: quality capstone

**Changed:** IPC contract test now scans src/components too (covers the Shot
Library / Settings channels, +7 checks → 108 tests). Memoized the board's
sortedImages (useMemo) so selection/note edits don't re-sort the image list.
Fixed SVG shot thumbnails: raster formats get a PNG thumb; SVG/unsupported leave
no thumb and the library shows a placeholder (previously a wrong-format copy
rendered broken).

**Learned:**
- Contract tests must scan EVERY directory that calls the IPC shim, not just
  modes — new components silently bypassed the guard until added.
- Thumbnail fallbacks must respect format: copying an SVG into a `.png` thumb
  and serving it as image/png renders broken. Prefer an honest placeholder.

**Maturity state (2.5.0):** four modes + undo/redo, persistent shot library,
crop, settings, accessibility focus rings, file-based autosave, network ad
blocking (macOS), OCR, GIF playback, URL scraping. 108 frontend tests, 4 Rust
tests, 30-assertion hidden end-to-end self-test, CI on macOS/Windows/Linux.

## Deliberate decisions

- **Bundle identifier stays `com.floatpad.app`** despite the tauri warning
  (ends with `.app`): changing it would orphan the user's existing prefs and
  WKWebView localStorage (bookmarks, theme, onboarding state).
- **Electron v1 shell retired** (v2.1.2) after the full audit; `src/ipc.js` is
  Tauri-only and the vitest contract test guarantees every channel used by any
  mode is handled.
- **Opacity applies to the calling window** (panels included) — intentionally
  better than v1, where a panel's slider changed the main window.
- Known remaining gaps: click-through hover forwarding (no Tauri API), Linux
  window opacity (tao exposes no GTK alpha), WebGPU board renderer (future
  performance option, not needed at current scale).
